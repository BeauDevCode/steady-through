## Queued learning ownership and deletion

Change controller learning updates to `Future<void> updateLearning(LearningData Function(LearningData current) change, {int? expectedRevision, bool Function()? isActive})`. Capture a default replacement revision at invocation and evaluate ownership plus `change(current.learning)` inside the write queue. Session source/pause/resume operations patch only current control fields; copy input source sets defensively. Closed sessions and replaced documents reject queued intents. Ordinary queued control changes remain ordered and must not use observation-generation equality.

For Session feeling saves, capture replacement revision and `_generation` before any motion await, then enforce both plus current foreground/alive/unpaused/source/vehicle conditions before the controller's queued write. Add optional expected-revision/active guards to `recordLearning` for Session use; preserve existing direct callers. Capture the canonical committed example from `LearningData.record(...).examples` inside the mutation, since record creates a safe new instance; return that receipt after persistence without looking it up in subsequently changed controller data. Preserve exact-instance Undo and primary-failure behavior.

Explicitly request residual cleanup after event deletion (including its check-ins), individual check-in deletion, clear game history and every confirmed document replacement, alongside existing People/learning/rating/Delete-all cleanup. Active-save failure must leave state unchanged; cleanup failure after a committed change produces the existing warning and must not invite duplicate saving. Exports and OS backups remain outside app cleanup; no forensic-erasure claim.

## Stable submitted forms and Help feedback

During vault create/unlock, event create/edit, action add/edit and check-in submission, submitted text fields are read-only until the operation completes. Check-in intensity choices and event guide/starter choices are disabled during save as well. At320px/200% text, the complete Confirm passphrase (setup and backup) and Optional description labels wrap above their fields with full editable-field semantic labels, following the existing optional-phone pattern. Existing navigation and cancellation semantics remain; preserve current controls, selected data and retryable input on failure. Do not broaden this task to a new routing or form-state architecture.

Help's existing Copy fallback catches clipboard exceptions, keeps the number visible and provides generic failure feedback. Use route/lifecycle/mounted guards to avoid late feedback on a different view, suppress duplicate pending copies if required, and never claim success/delivery after failure. Native phone/SMS behavior is unchanged. Clipboard regressions use a controlled method-channel failure; no real clipboard mutation.
