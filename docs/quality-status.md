# Quality status

_Life-event guidance source status: November 6, 2026 (UTC)_

The current source is **1.2.0+5**, preparing **v1.2.0-preview.1**. Each event has a voluntary General, School & growing up, Adult life changes, Caring for someone, or Later life changes guide, with standard/Simple words prompts and selectable starter steps. The five journey stages remain unchanged. Saved steps retain their IDs, text, order and completion states through guide/style changes. Guide choice and event text are not learning inputs; explicitly enabled in-app activity can still count ordinary taps and navigation as aggregates. Support stays free and offline with every learning source off.

Version 3 is the write format; validated version 1/2/3 documents are readable. Legacy events receive General context while retaining existing actions. Invalid version 3 context is rejected before replacement confirmation. Older apps cannot read new version 3 vaults or exports; this is a one-way read-compatibility boundary, with no silent downgrade or plaintext fallback.

### Defects found during v1.1.1 native validation

Earlier attempts exposed a missing text direction on the inactive privacy-cover icon; a lifecycle widget regression failed before the one-line fix and then passed. Native text-entry retry needed an actual field tap after submit unfocused the real input connection; the harness keeps its controller, button-state and real-store retry assertions.

On a healthy iOS Simulator, an earlier sources-off run displayed a real Motion & Fitness permission alert, followed by an actual inactive lifecycle notification. The app's eager motion manager and passive instance operations were removed from that path. The final unchanged three-case suite passed with the optional manager absent until an explicit permission action or an active, opted-in, OS-authorized session. Reviewers inspected the final screen capture, which had no Motion & Fitness alert, and the lifecycle trace recorded no inactive transition. The earlier logs do not establish which individual Core Motion instance operation originally triggered authorization. Granted-permission and physical-motion behavior remain separate checks.

The CI investigation also found that a zero `bootstatus` exit could contain terminal **Data Migration Failed**. The helper now retains and validates that output, rather than equating process completion with readiness. Runtime metadata supports current chosen/default keys and older preferred/override keys, and requires an exact available build. The iOS job pins Xcode 26.5 on macOS 26 because the hosted image installs its default runtime; the rolling Xcode 26.6 requested a patch runtime absent from the captured inventory. [GitHub's runner toolset](https://github.com/actions/runner-images/blob/main/images/macos/toolsets/toolset-26.json) documents that installation policy. A progressing Linux dependency download also exceeded the former ten-minute limit; the install step now has a finite twenty-minute budget. The final linked run passed without a job retry. Superseded failed or cancelled runs are not release evidence.

## What is implemented, and what remains limited

- Guidance offers five voluntary event contexts, each with prompts and selectable starter steps across the same five stages. A helper can read along without a separate account. This is bundled planning content, not a clinical program, inferred age or caregiving classification, or established effectiveness result across age groups. No birth date is required. The [guidance content note](guidance-content.md) records the original copy's source basis and limits.
- The whole app stays free. Planning, tools, people and help remain available with every learning source off and every OS permission declined. Manual and in-app learning sources have no device-permission requirement on any of the five target platforms.
- Saved app data/settings and learning records use an authenticated encrypted vault; new exports are independently encrypted `.steady` documents containing version 3 data. Validated versions 1/2/3 remain readable; older apps cannot read new v3 documents. Legacy JSON is still accepted after validation and replacement confirmation. Migration removes known plaintext files only after authenticated encrypted read-back, and surfaces cleanup failures. A committed save/import/clear remains successful if later cleanup fails, with a persistent warning that older copies may still contain earlier records. Ordinary saves cannot dismiss that warning; confirmed cleanup is required. Source JSON files, exports and OS backups outside known app paths remain under their owner's control.
- macOS implements foreground collector-session activation counts and screen-awake session minutes; these do not measure attention. Its observer stops when the app loses focus, so it cannot observe switching among other apps and the count may stay zero. Android implements aggregates from the last 60 minutes of UsageStats events and optional session-only Play services Activity Recognition. iOS implements optional Core Motion summaries; history may be delayed, and cross-app usage is unavailable without the Family Controls entitlement and Screen Time extensions. Windows/Linux system usage and motion remain unavailable. None of these statements establish hardware validation.
- Core Motion's current classification is change-driven, not a periodic heartbeat. A known vehicle context must remain active until a new known classification or stop; unknown readings cannot establish that movement ended. Possible vehicle movement is uncertain and does not identify a driver or passenger. Interactive reflection prompts are suppressed in this context, with help still available.
- The personal model uses explicit labels and comparable aggregates. It needs at least 20 eligible examples across seven observation days, at least five examples of each of two concrete labels and two comparable features before a tentative match is possible. Insufficient, contradictory or shifted evidence remains insufficient/uncertain. Manual-only labels can describe a self-reported trend. This is not a clinical instrument or an established emotion-accuracy result.
- A review after about 60 days trains only on earlier examples and evaluates on later held-out examples and a majority-label baseline. Coverage and improvement checks must pass before adoption; otherwise the revision stays. Learning is bounded to 180 days/1,000 examples. Time elapsed does not guarantee improvement.
- Readable records and a derived key exist during unlock. Lock closes the owned key object, but runtime/OS memory erasure and protection of an already compromised unlocked endpoint are outside the guarantee. Returning after five minutes away requires unlock; this does not claim a background timer erased a suspended process's key. There is no recovery server for a forgotten passphrase.

## Still required before a general store release

Use the [manual device-validation guide](device-validation.md) to record these observations on each platform/build. Its checks are preparation, not executed results.

- Run complete flows on physical iOS and Android devices: vault setup/unlock/lock, wrong passphrase, migration/cleanup warnings, encrypted export/import, file dialogs, phone/SMS handoff, background/resume, interrupted writes, rotation, keyboard and accessibility settings.
- Validate supported sources using real permission grants, denial/revocation, no-data/unsupported states, session stop and late callbacks. Exercise Android with and without usable Google Play services; verify UsageStats observation-window limits. Validate Core Motion's change-only vehicle state over a sustained session and after suspension, and confirm that unknown movement is not treated as emotional evidence.
- Walk through macOS activation/session duration and stop-on-lock/background behavior. Perform manual Windows and Linux usability checks in addition to the current automated native vault/backup flows.
- Review crypto/recovery/deletion boundaries and inference wording again for distribution changes, resolving material findings and rerunning affected checks. Inspect current guidance, vault and Insights screens in light/dark, reduced-motion, narrow and 200% text configurations; source review and automated layouts do not establish native screen-reader usability.
- Perform VoiceOver, TalkBack and keyboard-only walkthroughs on the native apps, including source controls, owner/OS permission dialogs, unavailable readings, errors and safe vehicle-context behavior.
- Observe people using the guidance, including caregivers/helpers and older adults, and revise unclear steps. Automated tests do not establish whether the guidance is understandable for every age or that it improves health outcomes.
- Configure distribution signing, Apple notarization and store records, then test signed packages through their distribution channels. CI artifacts are not store approval, notarized distribution or a signed release guarantee.

The [README](../README.md), [privacy details](../PRIVACY.md) and [contribution guidance](../CONTRIBUTING.md) describe the intended behavior and review boundaries. Any discrepancy with current code or observed runtime behavior is a defect to resolve, not a reason to claim broader validation.
