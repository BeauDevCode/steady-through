The [quality record](../quality-status.md#current-150-preview--verified-evidence) separates current observations from [historical 1.4 evidence](../quality-status.md#current-140-preview--verified-evidence).

1. **Reuse shared trusted-person cards.** Help previews at most the first three people in stored order, without ranking or relationship inference, before More support. View all saved people opens full People management; an empty state explicitly offers Add person. Help retains crisis content, Back and breathing pause/return behavior. The [design](../superpowers/specs/2026-11-06-quick-support-design.md) records why shared cards plus a full route were chosen over link-only navigation or duplicated Help cards.
2. **Keep contact actions explicit.** Call, Text and Copy occur only after a tap on the visible expected record. Failed/throwing/unavailable handlers report failure and leave a visible number/copy fallback; handoff is not delivery. Pending actions suppress duplicates, clipboard errors are reported, and late feedback does not overwrite another view. No contact permission, cloud service, active event or enabled learning source is required. No real person was called or texted, and actual OS handoff/dialog behavior has not been validated.
3. **Edit existing encrypted records.** Shared Add/Edit uses prefilled name/optional phone, Save and Cancel. Trim input, reject blank names and allow clearing the number while preserving ID/order and other records. Preserve confirmed removal, retryable input after primary failure, duplicate-save guards and committed-save cleanup warnings. Editing/removing requests cleanup of known residual copies; external exports/OS backups remain outside that control. Names, phones and relationships never become learning examples or features; generic opted-in UI aggregate counters retain their existing scope.
4. **Focus the existing exact action.** Home's Go to this step opens Your next step for an event ID, action ID and document-replacement revision. The view reads current target data, offers explicit Mark step done/Undo completion, Back to Home, Help now and View full path, and performs no completion on navigation or automatic advancement. No-action/all-done/completed-event states retain full Path access. This avoids scroll-to-lazy-stage assumptions and adds no persisted task type.
5. **Guard ownership before serialized persistence.** Current-document/expected-record/active-event checks and alive/foreground guards reject disposed, replaced, removed or changed targets before queued writes begin. Same-ID imported records cannot acquire an old action. Current data is mutated inside the write queue so unrelated concurrent writes survive. Already-started atomic saves may finish without popping another route or showing late success; primary failure leaves a retryable action unchanged.
6. **Capture revision when a dialog opens.** The new Add person and existing Add a rating/Clear ratings dialogs lazily initialized their document-replacement revision. If import occurred before its first use, an old dialog could acquire the imported document's revision and add to or clear its records. Eager initialization at dialog opening binds it to the original document. Three new regressions were observed RED before the fix and PASS after it; stale edit/focus targets retain their identity/revision guards.
7. **Keep the data and sensing contract.** Write schema **4**, read strictly validated **1/2/3/4**; there is no schema 5. Encryption envelope, KDF, independent export passphrases, native adapters, dependencies, permissions, learning thresholds and source consent remain unchanged. Imported system-source consent resets off. Support stays free/offline with every source off, with no birth date or contacts access. Older apps supporting only up to 3 cannot read new 4 files; preserve a usable earlier backup if return is needed.
8. **Extend persistence evidence without overstating UI execution.** The real encrypted unit/native backup fixtures now include edited fictional people, cleared optional phone, stable ID/order, other records/settings and the exact focused-completion controller API alongside guidance and ratings. The original three native case names remain unchanged. The extended backup fixture passed on all five native runtimes; file gateway/confirmation callbacks remain scripted. The fixture does not execute native contact handoffs, Help/People navigation or the focused route.
9. **Keep verification gates explicit.** All three capture profiles passed; all 24 generated fictional Help/People/Edit/focus captures were visually inspected. These captures show non-saving states; the read-only fix applies only while saving. The renderings do not validate native accessibility. Final local verification, whole-branch review and one regression-verified fix pass completed as recorded below. Exact-source seven-job CI, thirteen artifact ZIP/source/run/job bindings, six full package payloads/metadata, native cases, device/archive checks and ten assets with exact public body/tag/hash/anonymous verification are complete. Public-main ancestry and documentation-only equivalence were verified at the observation recorded in the [publication snapshot](1.5.0-publication.json); later documentation-only records preserve the tested application source.
