# 1.4.0 implementation decisions and evidence

## Current 1.4 work in progress — CI and release pending

The working app version is **1.4.0+8**. This records the intended and implemented scope pending final review/verification; it does not assert a successful CI run, tested source hash, native execution count or published release. The [quality record](../quality-status.md) will carry those observations when verified. Earlier 1.3 evidence is historical.

1. **Store explicit preferences.** Helpful and Not this time are personal opinions about Grounding, Breathing or the Path game. The [research-informed design](../superpowers/specs/2026-11-06-what-helps-design.md) explains why a bounded transparent history was selected instead of an effectiveness/ranking model. Ratings are separate from feelings, learning examples, calibration and game-round feelings. Skip, Stop, Back, Help and reaching an ending save nothing by themselves.
2. **Offer quiet stopping points and preserve control.** Grounding's ending, Breathing's explicit Done for now after Start, and the game's Finish view offer collapsed optional prompts. They do not intercept exits. A manual opinion is allowed even after stopping early. Breathing pauses on background or Help without automatically resuming, and Start again begins a fresh attempt. Reduced motion uses a static circle with readable pace text.
3. **Retrieve rather than infer.** What helps you shows descriptive per-tool counts and latest answers. A tool to revisit uses the most recent Helpful answer only among tools whose latest retained answer is Helpful, explains its date/reason and opens after a tap. A negative answer does not hide/reorder ordinary tools. No leaderboard, quota, proportions, emotion inference, automatic intervention, notification or treatment-benefit claim is added.
4. **Keep ownership independent of sensing.** Show optional ratings after tools and Use my ratings for ideas default on and persist independently. Hiding prompts leaves manual add/history management available. Source-off or learning-paused states do not block ownership. Only the existing optional session's current possibleVehicle flag suppresses feedback/mutation controls; Help/Back stay reachable, missing motion remains unknown and no source/grant is added. This cannot guarantee driving detection.
5. **Bound encrypted data and preserve exact identity.** Each record contains only ID, UTC time, tool and answer. The active history excludes future entries, retains the inclusive last 180 days and keeps at most 1,000 records in deterministic time/ID order. Corrections preserve ID/time/tool, and Undo/delete require the exact unchanged receipt. All data/settings remain in the existing encrypted vault and independently encrypted export; encryption envelope, KDF and native adapters stay unchanged.
6. **Guard the moment of mutation.** Serialized writes check captured document-replacement revision and an alive/foreground/attempt guard before repository persistence begins. Import, Delete all, backgrounding, board replacement or disposed prompts reject stale queued actions. An atomic write already started may finish without showing late success on another route/attempt. Failed writes retain a retryable choice; committed-save cleanup warnings remain distinct from unsaved actions.
7. **Separate deletion scopes and external copies.** Pruning runs at unlock, export and every committed mutation for ratings and feeling learning. Corrections and removed records request cleanup of known older local copies; a failed purge can leave a warning after the active save succeeded. Clear ratings preserves both rating settings and unrelated records. Clear learning/game history preserve ratings; Delete all resets them with other app data. Exports and OS/provider backups require separate deletion.
8. **Advance the document format explicitly.** Write schema 4; read strictly validated 1/2/3/4. Version 4 requires the toolFeedback object, strict enums/booleans/keys, valid timestamps, unique IDs and at most 1,000 imported records. Earlier versions containing the new field are rejected. Validated older documents migrate with empty ratings/default-on settings while preserving existing guide/actions/check-ins/appearance/reading/learning. Imported ratings/settings are retained while native usage/motion consent resets off. Apps that support only up to 3 cannot read new 4 vaults/exports: preserve a usable older backup if a return is needed. No silent downgrade/plaintext fallback exists.
9. **Keep evidence tied to its source and limits.** Final format/analyzer/Flutter/helper results, fresh whole-branch review, exact-source seven-job CI, all original three native case names per runtime, six packages, public hashes/access and publication are pending. The encrypted native backup fixture includes all tools/both answers and both settings; execution must be recorded separately. Synthetic feedback captures are planned for `docs/screenshots/what-helps/` and need visual inspection. Physical grants/devices, native assistive technology, real OS dialogs, signing/notarization and clinical or human outcomes remain unexecuted work.

The [manual device guide](../device-validation.md) and [iOS distribution handoff](../ios-distribution.md) preserve the remaining owner/device steps. No prior-release count or package result is evidence for 1.4.
