# 1.3.0 implementation decisions and evidence

1. **Research-informed scope.** Preserve the existing Flutter/local-vault architecture and implement visible personal feedback first. The JITAI framework and primary sensing research do not establish that this app can detect feelings from games/motion. Sources, alternatives and inference limits are in the [design](../superpowers/specs/2026-11-06-saved-moments-design.md).
2. **Correct the original observation.** History edits replace only the selected feeling label. They keep ID, saved/observed times and exact snapshot fields; choosing a feeling in the current reflection creates a new moment. Undo targets the exact committed record and checks both its ID and instance, never a whole-document restore.
3. **Discard stale derived results.** Any changed/deleted/retained-away evidence clears the saved model, revision, adoption/correctness counters and obsolete review reason. Existing review anchors remain while moments remain; an empty history clears them. A history mutation does not itself adopt a replacement model.
4. **Keep personal summaries distinct from model coverage.** A seven-day summary uses all retained self-reports, including Unsure, independently of source access. Diagnostics reuse actual training/assessment logic and current source filtering. Coverage is not accuracy. The existing 60-day evaluation rules and thresholds remain unchanged.
5. **Keep compatibility and privacy boundaries.** Schema3/JSON shape, encrypted envelope, KDF, native source adapters and default-off consent stay unchanged. Editing requests residual cleanup; a cleanup failure after a committed write is reported separately. External exports are outside local deletion control.
6. **Separate code, native packages and field evidence.** Local verification records 309 Flutter tests, 88 helpers, no analyzer issues and 86 formatted Dart files unchanged. Thirteen synthetic capture cases were inspected. Fresh whole-branch review completed; three reproduced display/retention findings were fixed and the full suite passed. Exact-source CI, binary metadata and public hashes remain prerequisites before claiming the new release verified. Physical devices/grants, native assistive technology, real OS dialogs, signing/notarization and human/health outcomes remain separate unexecuted work.

Publication evidence will identify the exact CI source/tag and any documentation-only main successor in [quality status](../quality-status.md).
